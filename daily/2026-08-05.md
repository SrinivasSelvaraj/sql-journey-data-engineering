## What I studied

- Transactions: BEGIN, COMMIT, ROLLBACK, SAVEPOINT
- Set operations: UNION vs UNION ALL, INTERSECT, EXCEPT

## One SQL query or idea

```sql
-- SAVEPOINT lets you roll back part of a transaction without losing everything
BEGIN;
INSERT INTO job_postings_fact (job_id, job_title_short) VALUES (1, 'Data Engineer');
SAVEPOINT after_insert;
DELETE FROM job_postings_fact WHERE job_id = 99;  -- mistake
ROLLBACK TO SAVEPOINT after_insert;               -- undo just the delete
COMMIT;
```

## What I learned

- ROLLBACK TO SAVEPOINT is powerful for partial undos inside a long transaction
- UNION removes duplicates (slow); UNION ALL keeps them (fast) — always prefer UNION ALL unless dedup is required
- INTERSECT and EXCEPT are rare but clean alternatives to EXISTS/NOT EXISTS subqueries
